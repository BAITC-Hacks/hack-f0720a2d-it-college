# Руководство для команды

Проект — модульный монолит на FastAPI. Перед началом работы прочитайте этот файл. Быстрый локальный запуск описан в [LOCAL_RUN.md](LOCAL_RUN.md).

## Границы модулей

Каждая предметная область живёт в `app/modules/<module>/` и содержит `router.py`, `schemas.py`, `service.py`, `models.py`.

- `router.py` знает HTTP и зависимости FastAPI, но не содержит бизнес-логику.
- `schemas.py` содержит только Pydantic-схемы входа и выхода.
- `service.py` содержит бизнес-правила и является публичным интерфейсом модуля.
- `models.py` содержит только SQLAlchemy-модели своего модуля.

Модуль не импортирует `models.py` другого модуля. Межмодульные операции выполняются только через функции `service.py`. Исключение — `app/db.py`, где модели централизованно импортируются для регистрации metadata SQLAlchemy.

## Распределение работы

Чтобы трое разработчиков не конфликтовали, удобно делить работу так:

1. Конструктор задачи: `users`, `tasks`, `ai`, `rating`.
2. Каталог и команды: `catalog`, `teams`.
3. Отклики, фронтенд и интеграция: `proposals`, `static`, сквозные тесты.

Изменения общих файлов (`app/main.py`, `app/db.py`, `requirements.txt`, `AGENTS.md`, `LOCAL_RUN.md`, `start.py`, `start.bat`) заранее согласовывайте. Не меняйте публичные схемы или сигнатуры сервисов без уведомления команды.

## Инварианты продукта

- Текущий пользователь задаётся заголовком `X-User-Id`; паролей в MVP нет.
- Создавать и публиковать задачи может только бизнес.
- Публиковать можно только подтверждённую задачу.
- Низкий рейтинг не скрывает опубликованную задачу и не запрещает отклик.
- Команда сама отправляет отклик. Бизнес вручную принимает или отклоняет каждый отклик.
- Автоматическое назначение команды запрещено.
- Рейтинг пересчитывается при каждом сохранении карточки.
- AI-слой не выдумывает факты и пока не вызывает внешние API.

## Интерфейс и интеграция (добавлено 23.09.2026)

- Рабочий интерфейс реализован по пользовательскому `design/HANDOFF.md` и экранам `design/screens*.py`. Не перезаписывайте исходные макеты при изменении приложения; генераторы дизайна не исполняются сервером.
- Стек фронтенда остаётся HTML/CSS/ES-модули без фреймворка и сборки. FastAPI отдаёт `/` и `/static`; все HTTP-вызовы находятся только в `static/js/api.js`.
- `app.js` управляет ролью, пользователем и hash-маршрутами; `catalog.js`, `constructor.js`, `task.js`, `proposals.js` отвечают каждый за свои экраны. Общие компоненты — `helpers.js` / `ui.js`. Перед изменением общего компонента проверьте все экраны, которые его используют.
- `tokens.css` и `components.css` перенесены из дизайна, `style.css` отвечает за компоновку и адаптивность. Сохраняйте общую типографику, палитру и табличный вид каталога/сравнения команд.
- SQLite/API — источник истины. LocalStorage с префиксом `ai-sana:` содержит выбор пользователя, фильтры и резервные копии форм; записи черновиков разделены по пользователю и задаче. UI не вычисляет бизнес-рейтинг, а показывает серверный ответ. Если меняете веса или пороги в `rating/service.py`, синхронизируйте поясняющие подписи и шкалы в `static/js/ui.js` / `helpers.js`.
- Автосохранение карточки последовательно отправляет `PATCH` после паузы ввода. При уходе с экрана обработчики и таймеры очищаются; несохранённый ввод остаётся локально для восстановления.

### Дополнения публичных контрактов

- `GET /api/tasks`: только текущий бизнес, все его задачи. Сервисы `tasks.list_owned` и `tasks.owned_ids` нужны кабинету и ограничению видимости откликов.
- `GET /api/proposals`: бизнес видит отклики своих задач, команда — собственные. Сервис `proposals.list_for_user`.
- `POST /api/proposals/{id}/reopen`: только владелец задачи, перевод из `accepted` / `rejected` в `pending`; уже `pending` → `409`. Это ручная отмена решения, не автоматическое назначение.
- `CatalogTask.proposals_count` — число всех откликов, получаемое через `proposals.counts_by_task`; каталог не импортирует модель `Proposal`.
- Изменение подтверждённой карточки сбрасывает её в `draft`, чтобы перед публикацией сведения подтвердили снова. Опубликованная карточка остаётся опубликованной при редактировании.
- Ссылка отклика проверяется как HTTP(S); строки формы отклика обрезаются по краям до проверки длины.

Перед передачей UI проверяйте сценарий «бизнес создаёт и публикует → две команды откликаются → бизнес выбирает/отклоняет/отменяет решение», повторное открытие страниц, мобильные фильтры, горизонтальную прокрутку сравнения и консоль браузера. Автотесты новых правил находятся в `tests/test_workspace.py`.

## О проекте AI Sana

MVP для практического хакатона: представитель бизнеса создаёт черновик задачи, получает уточняющие вопросы, редактирует карточку и видит прозрачный рейтинг готовности. После ручного подтверждения задача публикуется в общем каталоге. Студенческие команды сами выбирают задачи и отправляют отклики, а владелец задачи вручную принимает или отклоняет каждый из них.

Автоматического назначения команд в проекте нет.

## Стек

- Python 3.11
- FastAPI
- SQLAlchemy 2.0
- SQLite
- Pydantic v2
- статические HTML, CSS и JavaScript без frontend-фреймворка

FastAPI одновременно отдаёт API и каталог `static/`, поэтому для MVP нужен один сервер.

## Архитектура

Проект собран как модульный монолит:

```text
app/
  main.py              сборка приложения, роутеры, CORS и статика
  config.py            настройки окружения
  db.py                engine, SessionLocal, Base и get_db
  modules/
    users/              выбор пользователя и роли
    tasks/              черновик, карточка и статусы задачи
    rating/             чистый расчёт рейтинга
    ai/                 заменяемая локальная AI-заглушка
    catalog/            опубликованные задачи и фильтры
    teams/              профили команд
    proposals/          отклики и ручное решение бизнеса
  seed/
    seed.py             загрузчик демонстрационных данных
    data/               JSON-наборы
static/                 работающий интерфейс по макетам из design/
tests/                  smoke-тесты модулей и проверки доступа
```

В каждом предметном модуле есть `router.py`, `schemas.py`, `service.py`, `models.py`. Чужие ORM-модели модули напрямую не импортируют: взаимодействие проходит через публичные функции сервисов. Правила совместной работы и рекомендуемое деление задач для трёх разработчиков описаны в начале этого файла.

HTTP-запрос проходит через `router → schemas → service → models → SQLite`. `users.service` проверяет `X-User-Id` и роль. Модуль `tasks` вызывает только `ai.analyze_draft`, `ai.build_card` и `rating.calculate`; каталог получает опубликованные задачи через `tasks.service`, количество откликов — через `proposals.service`. Отклики проверяют задачу и команду через сервисы `tasks` и `teams`. Модели регистрируются централизованно в `db.py`, таблицы создаются при старте приложения.

Основные сущности: `User` (роль, необязательная связь с командой), `Task` (владелец, описание, поля карточки, статус, рейтинг и расшифровка), `Team` (название, интересы, навыки, технологии), `Proposal` (задача, команда, идея, план, срок, ссылка, решение бизнеса). SQLite хранит задачи и отклики; браузер хранит выбранного пользователя, фильтры и резервные копии незавершённых форм. Это не заменяет серверную проверку доступа.

### Фронтенд

Сборщика, Node.js и отдельного frontend-сервера для запуска не требуется. `index.html` подключает ES-модули; hash-навигация позволяет обновлять любую открытую страницу.

| Файл | Ответственность |
|---|---|
| `static/js/app.js` | Оболочка, переключение роли/пользователя, маршруты, загрузка и ошибки |
| `static/js/api.js` | Все `fetch`, заголовок `X-User-Id`, обработка HTTP-ошибок |
| `static/js/catalog.js` | Каталог, поиск, фильтры, сортировки, рекомендации по интересам |
| `static/js/constructor.js` | Описание → вопросы → карточка с автосохранением → подтверждение → публикация |
| `static/js/task.js` | Просмотр карточки и отправка отклика командой |
| `static/js/proposals.js` | Кабинет бизнеса, сравнение предложений, решения, личные отклики команды |
| `static/js/helpers.js`, `ui.js` | Общие формы, сообщения, экранирование текста, рейтинг и визуальные компоненты |
| `static/css/tokens.css`, `components.css`, `style.css` | Токены и компоненты переданного дизайна, компоновка и адаптивность |

Макеты-источники находятся в `design/`: их генераторы не нужны работающему серверу. Цвета, Onest / JetBrains Mono, табличный каталог и сравнение команд перенесены из этих макетов. Шрифты загружаются из Google Fonts; без сети используются системные запасные шрифты. Данные, счётчики и рейтинг всегда реальные, а не зафиксированные значения макета. На телефоне фильтры и список задач сворачиваются; таблица сравнения прокручивается горизонтально.

## Рейтинг готовности

Рейтинг рассчитывается чистой функцией `app.modules.rating.service.calculate` и обновляется при каждом сохранении задачи.

| Поле | Вес |
|---|---:|
| Контекст | 10 |
| Потребность | 10 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт с бизнесом | 10 |

Контекст и потребность вместе дают требуемые 20 баллов. Пустое поле даёт 0, текст короче 30 символов — половину веса, текст от 30 символов — полный вес. Ответ содержит общий балл, уровень, расшифровку по полям и подсказки о недостающих сведениях.

Уровни:

- `0–39` — `draft`, «Черновик»;
- `40–69` — `working`, «Рабочая»;
- `70–89` — `ready`, «Готовая»;
- `90–100` — `priority`, «Приоритетная».

Веса, пороги и минимальная длина вынесены в константы в начале `app/modules/rating/service.py`.

## Правила каталога и откликов

- В каталог попадают только задачи со статусом `published`.
- Публиковать можно только задачу со статусом `confirmed`.
- Каталог сортируется по рейтингу по убыванию.
- Поддерживаются фильтры `industry` и `level`.
- Низкий рейтинг не скрывает опубликованную задачу и не запрещает отклик.
- Отправить отклик может только пользователь роли `team`, связанный с профилем команды.
- Бизнес видит отклики только своих задач, команда — только собственные отклики.
- Принимать/отклонять отклики и возвращать их на рассмотрение может только владелец задачи.
- Одна команда может оставить один отклик на задачу. Можно принять несколько команд; остальные отклики не меняются автоматически.
- Решение всегда ручное; сервис не выбирает и не назначает команду автоматически.
- Изменение подтверждённой, но ещё не опубликованной карточки возвращает её в `draft`: перед публикацией требуется повторное подтверждение. Опубликованную карточку можно дополнять без снятия с каталога.

## AI-заглушка

Внешние API и дополнительные AI-зависимости не используются. Модуль `app/modules/ai` предоставляет два стабильных интерфейса:

- `analyze_draft(raw_text)` возвращает недостающие поля и минимум три шаблонных вопроса;
- `build_card(raw_text, answers)` раскладывает только исходный текст и ответы пользователя по полям карточки.

Вход и выход валидируются Pydantic-схемами. Реальную реализацию можно подключить позже внутри этого модуля, не меняя задачи и другие модули.

## Установка и запуск

Самый простой способ на Windows: дважды нажмите `start.bat` или выполните `.\start.bat`. Все этапы подготовки выполняются автоматически. Подробная инструкция и решение проблем — [LOCAL_RUN.md](LOCAL_RUN.md). Ниже оставлены команды ручного запуска для разработчиков.

Из корня проекта в PowerShell (Python 3.11 должен быть установлен):

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
.\.venv\Scripts\python.exe -m app.seed.seed
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Активация `.venv` не обязательна: команды выше вызывают её Python напрямую и работают без изменения политики PowerShell. При желании можно активировать окружение через `.\.venv\Scripts\Activate.ps1` и использовать короткие команды `python` / `uvicorn`.

На Linux/macOS:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
python -m app.seed.seed
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

После запуска:

- интерфейс: <http://127.0.0.1:8000/>
- Swagger UI: <http://127.0.0.1:8000/docs>
- проверка состояния: <http://127.0.0.1:8000/health>

Повторный запуск seed безопасен: если пользователи уже есть, загрузчик не создаёт дубликаты.

После установки для следующих запусков нужна только последняя команда `uvicorn`. Оставляйте терминал открытым, остановка — `Ctrl+C`. Для разработки можно добавить `--reload`; без него после изменения Python-кода перезапустите сервер. Если порт занят, остановите предыдущий экземпляр либо укажите `--port 8001` и откройте соответствующий адрес.

Это локальный хостинг: адрес `127.0.0.1` доступен только на вашем компьютере. Публичный доступ в интернет не настроен. Не публикуйте этот MVP без настоящей авторизации: любой клиент может подставить чужой `X-User-Id`. Конфигурация БД задаётся `DATABASE_URL` в `.env`; по умолчанию используется локальный SQLite-файл. Ключи AI не нужны.

### Проверка через интерфейс

1. Откройте главную страницу, выберите «Бизнес» и пользователя Алию.
2. «Создать задачу» → введите описание → «Проверить полноту» → ответьте на вопросы → «Собрать карточку».
3. Дополните карточку: изменения сохраняются автоматически, баллы приходят с сервера. Нажмите «Подтвердить карточку», поставьте обе галочки и опубликуйте задачу.
4. Переключитесь на «Команда», выберите команду, найдите задачу в каталоге и отправьте идею, план и срок. Ссылка на прототип необязательна.
5. Вернитесь к тому же бизнес-пользователю → «Мои задачи» → сравните отклики → выберите или отклоните команду. «Отменить выбор» / «Вернуть на рассмотрение» возвращают отклик в `pending`.
6. У команды в «Мои отклики» нажмите «Обновить статусы». Изменения сохраняются после обновления страницы.

Каталог поддерживает поиск, выбор нескольких отраслей и уровней, сброс фильтров и сортировки по рейтингу, новизне или количеству откликов. «Рекомендации» — простой фильтр по интересам команды, не AI-подбор и не автоматическое назначение.

## API

Все продуктовые маршруты начинаются с `/api`:

```text
POST /api/users/login
GET  /api/users

POST  /api/tasks/draft
GET   /api/tasks
POST  /api/tasks/{id}/questions
POST  /api/tasks/{id}/card
PATCH /api/tasks/{id}
POST  /api/tasks/{id}/confirm
POST  /api/tasks/{id}/publish
GET   /api/tasks/{id}

GET  /api/catalog?industry=&level=
GET  /api/teams
POST /api/proposals
GET  /api/proposals
GET  /api/tasks/{id}/proposals
POST /api/proposals/{id}/accept
POST /api/proposals/{id}/reject
POST /api/proposals/{id}/reopen
```

Текущий пользователь передаётся заголовком `X-User-Id`. После seed пользователи `1` и `2` — бизнес, пользователи `3–7` — представители команд.

`GET /api/tasks` возвращает все задачи текущего бизнеса, включая черновики. `GET /api/proposals` возвращает доступные текущему пользователю отклики. `reopen` возвращает принятое/отклонённое предложение на рассмотрение; для уже ожидающего решения возвращается `409`. Каталог включает `proposals_count` — количество откликов всех статусов.

Пример проверки каталога:

```bash
curl http://127.0.0.1:8000/api/catalog
```

Пример создания черновика от пользователя бизнеса:

```bash
curl -X POST http://127.0.0.1:8000/api/tasks/draft \
  -H "Content-Type: application/json" \
  -H "X-User-Id: 1" \
  -d '{"title":"Новая задача","industry":"Образование","raw_text":"Хотим сократить время обработки обращений студентов"}'
```

Ошибки бизнес-правил возвращают подходящий HTTP-код и русское поле `detail`. Ошибки входных данных возвращают `422` с сообщением `Некорректные входные данные`.

## Тесты

```bash
pytest
```

Есть отдельные smoke-тесты для `users`, `tasks`, `rating`, `ai`, `catalog`, `teams`, `proposals`; формула рейтинга проверяется отдельно на пустых, коротких и полных значениях.

`tests/test_workspace.py` дополнительно проверяет изоляцию кабинетов, запрет чужих решений, ручной выбор без изменения других откликов, возврат на рассмотрение, повторное подтверждение карточки, дубликаты и валидацию формы отклика. Браузерные проверки выполняются отдельно от `pytest`: пройдите описанный выше цикл на широком и мобильном экранах, проверьте обновление страницы и консоль. Playwright не является зависимостью сервера.

## Ограничения MVP

- Нет регистрации, паролей и сложной ролевой модели.
- Нет реального AI-вызова: используется детерминированная локальная заглушка.
- Нет чата, уведомлений, календаря, файлового хранилища и проектного трекера.
- SQLite и один процесс рассчитаны на демонстрацию, а не на промышленную нагрузку.
- Нет realtime-обновления решений: используйте «Обновить статусы» или обновите страницу.
- Рекомендации учитывают только отрасль и интересы; настройки профиля команды пока не редактируются через UI.
