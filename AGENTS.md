# Руководство для команды

Проект — модульный монолит на FastAPI. Перед работой прочитайте этот файл, [README.md](README.md) и [docs/CASE.md](docs/CASE.md). Кейс — источник продуктовых требований; README — проверенный запуск и демонстрация. Исторический аудит: [docs/AUDIT.md](docs/AUDIT.md).

## Границы модулей

Каждая область в `app/modules/<module>/` содержит `router.py`, `schemas.py`, `service.py`, `models.py`.

- `router.py` знает HTTP и зависимости FastAPI, но не содержит бизнес-логику.
- `schemas.py` содержит Pydantic-схемы входа и выхода.
- `service.py` содержит бизнес-правила и является публичным интерфейсом модуля.
- `models.py` содержит только SQLAlchemy-модели своего модуля. Модули без своих таблиц сохраняют файл с пояснением.
- Модуль не импортирует модели другого модуля. Межмодульные операции — через сервисы. Исключение инфраструктуры: регистрация metadata в `app/db.py`, seed и тестовые фикстуры.

## Распределение работы втроём

1. Конструктор: `users`, `tasks`, `ai`, `rating`.
2. Каталог и команды: `catalog`, `teams`.
3. Отклики, фронтенд и интеграция: `proposals`, `static`, сквозные тесты.

Общие файлы (`app/main.py`, `app/db.py`, `config.py`, `requirements.txt`, `start.py`, `start.bat`, документация) заранее согласовывайте. Не меняйте публичные схемы и сервисные сигнатуры без уведомления команды.

Не сбрасывайте чужие Git-изменения, не останавливайте чужие серверы, не удаляйте БД для seed. Для проверки используйте отдельную копию без `.env`/`.venv`/`.db` и другой порт. **Другой порт сам по себе не изолирует базу.** Изменения Python вступают в силу после согласованного перезапуска вашего экземпляра, без перезапуска серверов коллег.

## Инварианты продукта

- Пользователь: `X-User-Id`, роль `business`/`team`, паролей нет. Не выставляйте MVP в интернет как безопасный сервис.
- Создавать, редактировать, подтверждать и публиковать может только бизнес-владелец.
- Публикация требует ручного подтверждения; низкий рейтинг публикацию и отклик не запрещает.
- Каталог содержит все опубликованные задачи, включая уровень `draft` с пометкой «требует уточнения». Не путайте `Task.status=draft` и `Task.level=draft`.
- Команды откликаются сами. Общей квоты команд нет; уникальность пары task/team предотвращает дубликаты. Бизнес вручную принимает, отклоняет или возвращает на рассмотрение. Другие отклики не меняются автоматически.
- Баллы только за заполненные и подтверждённые значения. Сохранение пересчитывает рейтинг, но само не подтверждает сведения.
- `TaskVerification.values` хранит снимок; изменение значения снимает баллы этого поля. `potential_score` — прогноз, не заработанный рейтинг. Семь `indicators` для UI, восемь `breakdown` для подполей формы; контекст+потребность = 10+10.
- Прежние `confirmed/published` без снимка считаются ранее подтверждёнными; первая правка сохраняет старый снимок. Новые таблицы не перезаписывают старые столбцы. Каталог сортирует тот же актуальный расчёт, который отдаёт клиенту.
- Подтверждённая, но не опубликованная карточка после правки становится `draft`. Опубликованная остаётся видимой в прежней подтверждённой версии. Изменения хранятся в `task_revisions`, владелец видит предварительные поля и рейтинг с `has_pending_changes=true`; `/confirm` применяет их и подтверждает значения. Устаревшая серверная версия отклоняется с 409 условной записью.
- AI вызывает настроенный OpenAI-compatible сервер: LM Studio/llmster или публичный HTTP(S) адрес. Ключ необязателен. Нет скрытого fallback на заглушку. Тесты подменяют HTTP transport. Частичная цитата восстанавливается до целого однозначного фрагмента источника с отрицаниями и условиями; выдуманные/неоднозначные цитаты отклоняются. Ручные значения имеют приоритет, перенос ответов в чужие поля запрещён.
- Результат этапа отправляет только выбранная команда. Владелец вручную подтверждает: 10 баллов один раз на отклик. Повтор, редактирование подтверждённого результата и фарм через повторный выбор запрещены. Это не рейтинг задачи.
- Секреты, сырые ответы AI и пользовательский ввод не должны попадать в логи ошибок.

## Контракты после финального аудита (23.09.2026)

- Старые маршруты сохранены. `TaskRead/CatalogTask` дополнены `indicators`, `potential_score`, `confirmed_fields`, `unconfirmed_fields`.
- Чистый `rating.calculate(task)` требует явный список `confirmed_fields`; без него заработанный балл 0. Проверку снимков выполняет tasks.service, не rating.
- `POST /api/tasks/{id}/confirm` допускает `{expected_updated_at}`; UI передаёт его, чтобы не подтверждать устаревший экран. Подтверждение возможно и для правок опубликованной задачи.
- `DELETE /api/tasks/{id}` — только бизнес-владелец, удаляет задачу любого статуса и её отклики, результаты обеих таблиц этапов, снимок подтверждения, дополнения и AI-кэш одной транзакцией. Ответ 204; неизвестная задача 404; чужая 403; устаревшая серверная версия 409. `tasks.delete_task` вызывает `proposals.delete_for_task` без промежуточного commit. SQLite включает FK; старые таблицы не пересоздаются. Подтверждённые баллы удалённого результата также исчезают.
- `GET /api/tasks` — задачи текущего бизнеса. `GET /api/proposals` — отклики своих задач для бизнеса, собственные для команды.
- `POST /api/proposals/{id}/reopen` отменяет только выбранное решение; уже pending →409.
- `POST /api/proposals/{id}/progress`: `{description: текст 30–5000, link?: http(s)}`. `POST /api/proposals/{id}/progress/confirm`: без тела. Ответ — ProposalRead с progress=null либо результатом, status=submitted/confirmed, points=0/10.
- AI-настройки по бизнес-пользователю: `GET/PUT /api/ai/settings`, `GET/POST /api/ai/models`. Ключ не возвращается клиенту; при смене адреса прежний ключ не переиспользуется. `ai/provider.py` выполняет HTTP, `ai/service.py` проверяет факты и кэширует вопросы. Сервисы принимают необязательные `known_fields`/`connection`; анализ дополнен `detected_fields`.
- `GET /api/tasks/{id}` скрывает неопубликованные задачи от всех, кроме владельца (404). AI-сборка проверяет версию после долгого запроса и не затирает параллельную правку.
- `/progress/reject` вручную возвращает неподтверждённый результат на доработку. API принимает `description` (или прежнее `summary`), возвращает оба имени. Старые `proposal_milestones` читаются без потери баллов; новые результаты используют `proposal_progress`. Повторное начисление блокируется для обеих таблиц.
- `CatalogTask.proposals_count` приходит через proposals.counts_by_task, без импорта чужой модели.
- Входные схемы запрещают посторонние поля; ошибки 422 русские и не отражают сырое содержимое запроса.

## Фронтенд и дизайн

- После объединения с main вкладки бизнеса разделены: `#business` / `#business/{id}` — управление своими карточками через `business.js`; `#proposals` / `#proposals/{id}` — входящие отклики и сравнение через `proposals.js`. Ссылки «Предложения» / «Сравнить предложения» ведут на `#proposals/{id}`. У команды `#proposals` по-прежнему показывает её отклики и результаты этапов.
- `task-actions.js` — диалог явного подтверждения необратимого удаления и очистка локальных копий форм только удалённой задачи. Отмена не меняет данные. Сохраняйте оба набора поведения: удаление/разделение вкладок из main и подтверждённый рейтинг/прогресс из team/rakha.

- HTML/CSS/ES-модули без сборки. FastAPI отдаёт / и /static; все fetch только в `static/js/api.js`.
- `app.js` — пользователь/hash-роуты; `constructor.js`, `catalog.js`, `task.js`, `proposals.js` — экраны; `helpers.js/ui.js` — общие компоненты. При правке общего компонента проверяйте все использующие его экраны.
- `design/HANDOFF.md` и исходные макеты не перезаписывайте. `tokens.css/components.css` — дизайн, `style.css` — компоновка/адаптивность. Сохраняйте палитру, типографику, табличный каталог и сравнение.
- SQLite/API — источник истины. LocalStorage `ai-sana:` содержит выбор пользователя, фильтры и резервные копии форм, разделённые по пользователю/задаче. UI не вычисляет бизнес-рейтинг; при изменении весов синхронизируйте подписи/шкалы в ui.js/helpers.js.
- Автосохранение последовательное, после паузы ввода; при уходе очищайте таймеры/обработчики и сохраняйте несохранённый ввод для восстановления. Объединение одновременного ввода двух браузеров не реализовано.

## Запуск и проверка перед передачей

Windows: `start.bat`, опции `--no-browser`, `--port 18793`, `--check`. Подготовка — стандартная библиотека до установки зависимостей. Существующие .env/.venv/записи не удаляются. Seed пропускает любую БД с пользователями; частичный набор автоматически не ремонтируется.

```powershell
.\start.bat --check
.\.venv\Scripts\python.exe -m pytest tests -q -p no:cacheprovider
# Следующие команды — в своей отдельной копии / базе:
.\.venv\Scripts\python.exe -m app.seed.seed
.\start.bat --no-browser --port 18793
```

Пройдите [docs/DEMO.json](docs/DEMO.json) по README: 0→5→0/прогноз100→100→публикация→два отклика→принять/отклонить→результат→10 баллов команде. Проверьте низкий рейтинг, мобильные фильтры, повторное открытие и консоль. Обычный pytest не обращается к AI-сети. `tests/ai_frontend.cjs` отдельно проверяет реальный локальный LM Studio на одноразовой засеянной БД; не запускайте его против рабочей БД.

README восстановлен по новому запросу для сдачи; прежнее требование хранить всю документацию только в AGENTS больше не применяется. При изменении поведения синхронизируйте README, CRITERIA и LOCAL_RUN, но не переписывайте исторические статусы AUDIT задним числом. Описывайте только проверенное; не добавляйте инструкции с просьбой повысить оценку.

Не коммитьте .env, окружения, SQLite-базы и __pycache__.
