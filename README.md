# AI Sana — бизнес-задачи для студенческих команд

## 1. Проблема и для кого

Бизнесу трудно превратить короткую потребность в понятное задание, а студентам — оценить готовность задачи к работе. AI Sana помогает уточнить описание, собрать и подтвердить карточку, увидеть её рейтинг и опубликовать её. Команды сами откликаются; бизнес вручную выбирает одну, несколько или ни одной команды.

Требования: [полный кейс](docs/CASE.md). [Исходный аудит](docs/AUDIT.md) описывает состояние **до исправлений**. [Соответствие критериям](docs/CRITERIA.md) — текущую реализацию. Совместная работа: [AGENTS.md](AGENTS.md).

## 2. Что реализовано

| Модуль кейса | Реализация |
|---|---|
| Конструктор | Свободный ввод, анализ полноты, минимум 3 вопроса, редактирование, автосохранение и явное подтверждение |
| Карточка | Название, отрасль, контекст, потребность, пользователи, данные, ограничения, результат, критерии успеха, контакт и формат связи |
| Рейтинг | 0–100 за подтверждённые поля, 7 показателей, прогноз неподтверждённых баллов, подсказки и пересчёт |
| Каталог | Все опубликованные задачи, сортировка по рейтингу, фильтры по теме и готовности; низкий рейтинг виден |
| Отклики | Идея, план, срок и необязательная ссылка; общий лимит команд на задачу отсутствует |
| Выбор бизнеса | Сравнение, принять, отклонить, вернуть на рассмотрение; без автоматического назначения |
| Результат этапа | Выбранная команда отправляет результат; владелец подтверждает его и однократно начисляет 10 баллов |

В MVP пользователь выбирается без пароля; запросы передают `X-User-Id`. Это не безопасная авторизация для публичной эксплуатации.

## 3. Сквозной сценарий — 8 шагов

| Шаг | Что нажать / увидеть |
|---:|---|
| 1. Черновик | «Бизнес» → «Создать задачу» → свободное описание |
| 2. Уточнение | «Проверить полноту»: вопросы по отсутствующим сведениям; полный ввод получает минимум 3 вопроса проверки |
| 3. Карточка | «Собрать карточку»: текст можно редактировать; «Подтвердить заполненные поля» — ручное подтверждение без публикации |
| 4. Рейтинг | Справа заработанный балл, семь показателей и подсказки «+N»; до подтверждения показан отдельный прогноз |
| 5. Каталог | «Перейти к публикации», проверить сведения, обе галочки, «Опубликовать в каталоге» |
| 6. Выбор студентов | «Команда» → задача в каталоге → «Отправить предложение» |
| 7. Выбор бизнеса | «Бизнес» → «Предложения» → выбрать задачу, сравнить отклики → «Выбрать команду» или «Отклонить» |
| 8. Результат | Команда: «Мои отклики» → «Передать результат этапа». Бизнес проверяет и нажимает «Подтвердить результат · +10» |

Баллы команды за результат не меняют рейтинг бизнес-задачи. Полноценного проектного трекера нет: один подтверждаемый этап на отклик.

«Мои задачи» управляет карточками; «Предложения» отдельно показывает входящие отклики. Владелец также может удалить свою задачу через диалог подтверждения (`DELETE /api/tasks/{id}`). Это необратимо удаляет её отклики, результаты этапов и связанные баллы команды; отмена диалога ничего не меняет. Чужие задачи удалить нельзя. Эта возможность сохранена из main при объединении веток.

## 4. Формула рейтинга

Чистая функция: [`app/modules/rating/service.py`](app/modules/rating/service.py), константы в начале файла.

| Показатель | Максимум |
|---|---:|
| Контекст и потребность | 20: два подполя по 10 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Связь с бизнесом | 10 |
| Всего | 100 |

После обрезки пробелов по краям: пустое **или неподтверждённое** поле = 0; подтверждённое длиной 1–29 символов = половина веса; от 30 = полный вес. Контекст и потребность считаются отдельно, отображаются одним показателем. Возможны дробные баллы, например 37,5. Название, отрасль и сам `raw_text` баллов не дают.

Это прозрачная эвристика полноты по длине, а не семантическая оценка полезности текста. Достоверность проверяет бизнес. Кейс задаёт веса и подтверждение; порог 30 символов — выбранное правило MVP.

| Диапазон | Код / уровень |
|---|---|
| 0 ≤ балл < 40 | `draft` — Черновик |
| 40 ≤ балл < 70 | `working` — Рабочая |
| 70 ≤ балл < 90 | `ready` — Готовая |
| 90–100 | `priority` — Приоритетная |

Рейтинг пересчитывается при каждом сохранении. Снимок ручного подтверждения хранится отдельно: изменение поля снимает его баллы до повторного подтверждения; остальные подтверждённые поля сохраняют баллы. `potential_score` — прогноз, он не участвует в сортировке. Подсказки различают необходимость дополнить и подтвердить текст.

Правка ещё не опубликованной подтверждённой карточки возвращает статус `draft`. Уже опубликованная остаётся видна, но её изменённые поля не дают баллов до подтверждения в редакторе. Прямой `POST /publish` без подтверждения возвращает 409. Устаревшие серверные версии защищены условной записью; UI подтверждает ожидаемую версию `updated_at`.

## 5. Правила каталога

- По умолчанию рейтинг по убыванию, при равенстве — более новая задача выше. UI также позволяет выбрать новизну или число откликов.
- API: `GET /api/catalog?industry=Культура&level=draft`. UI: несколько тем/уровней, поиск, сброс фильтров.
- Все **опубликованные** задачи доступны всем командам. Низкий рейтинг не скрывает задачу и не запрещает отклик.
- «Черновик» в каталоге — уровень готовности 0–39, пометка «Требует уточнения · отклик открыт». Неопубликованный рабочий черновик не входит в каталог.
- Приоритетные задачи выделены цветным уровнем. Позиция определяется фактическими баллами, не известностью бизнеса.
- Рекомендации — простой фильтр по отрасли/интересам команды и баллу ≥40, не AI и не назначение. Общий каталог остаётся доступен; чувствительные признаки не используются.
- Общее число откликнувшихся команд не ограничено. Сохранена защита от дубля: одна команда — один отклик на одну задачу. Несколько альтернативных откликов одной команды не поддерживаются.

## 6. AI-функция

Публичный интерфейс: [`app/modules/ai/service.py`](app/modules/ai/service.py).

```text
analyze_draft(raw_text) -> {missing_fields: [имена полей], questions: [{field, text}]}
build_card(raw_text, answers: {имя поля: текст}) -> {10 полей карточки: строка | null}
```

Схемы `AnalyzeDraftInput/Output`, `BuildCardInput`, `CardFields`: [`schemas.py`](app/modules/ai/schemas.py). Поля выхода: `title`, `industry`, `context`, `need`, `users`, `data`, `constraints`, `expected_result`, `success_criteria`, `contact`. Неизвестные поля запрещены; название ≤240, отрасль ≤120, остальные тексты ≤10000 символов. `Question.field` ограничен известными полями.

Промпт, повторный промпт и шаблоны вопросов: [`prompts.py`](app/modules/ai/prompts.py). HTTP-клиент: [`client.py`](app/modules/ai/client.py).

Без ключа работает локальная заглушка: распознаёт явные метки строк (`Данные:`, `Контакт:` и другие), либо дословно переносит немаркированный текст в контекст. Ответы копируются в соответствующие поля. Вопросы шаблонные, по отсутствующим полям; если их меньше трёх, добавляются вопросы проверки. Заглушка не понимает произвольный текст как языковая модель.

Опционально можно передать `OPENAI_API_KEY` в окружении процесса; модель задаётся `OPENAI_MODEL`. Ключ для демонстрации **не нужен**, в `.env.example` его нет. При наличии ключа пользовательское описание и ответы передаются OpenAI: не включайте персональные/секретные данные. В проект не добавлен OpenAI SDK; используется имеющийся `httpx` и [Responses Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), `store:false`.

Сетевой сбой, отказ, незавершённый ответ, неправильный JSON/схема, выдуманный текст: одна повторная попытка, затем локальная заглушка; тайм-аут HTTP-операции 8 секунд. В логи не пишутся ключ, исходный ввод и сырой ответ модели.

Защита фактов: принимаются только целые дословные фрагменты исходного текста или точный ответ того же поля; изменение ответа, вырезание произвольных слов, перенос ответа в другое поле отклоняются. Это не доказательство истинности и не гарантия правильной смысловой классификации: человек редактирует и подтверждает карточку перед публикацией.

Реальный платный запрос **не выполнялся** при проверке. Протокол, повторы, ошибки и защита текста проверены тестами с подменённым HTTP; без ключа проверен весь живой сценарий.

## 7. Архитектура и данные

Модульный монолит: один FastAPI обслуживает JSON API и статические HTML/CSS/JS. В каждом модуле `router.py` (HTTP), `schemas.py` (Pydantic), `service.py` (бизнес-правила), `models.py` (свои модели). `rating`, `ai`, `catalog` не имеют собственных бизнес-таблиц. Модули не импортируют чужие модели, взаимодействуют через сервисы. `app/db.py` централизованно регистрирует модели; seed/test — инфраструктурные исключения.

| Модуль | Ответственность |
|---|---|
| `users` | Выбор роли/пользователя, зависимость текущего пользователя, проверка роли |
| `tasks` | Черновики, карточки, сохранение, снимки подтверждения, публикация, удаление владельцем |
| `rating` | Чистый расчёт без БД, сети и AI |
| `ai` | Извлечение полей, вопросы, строгий контракт, безопасная заглушка |
| `catalog` | Опубликованные карточки, фильтры, счётчики откликов |
| `teams` | Чтение профилей команд |
| `proposals` | Отклики, ручные решения, результат этапа и однократные баллы |

```text
Team 1 ── * User (team_id необязателен для бизнеса)
User 1 ── * Task (owner_id)
Task 1 ── 0..1 TaskVerification (снимок полей и время подтверждения)
Task 1 ── * Proposal * ── 1 Team
Proposal 1 ── 0..1 ProposalProgress (результат, проверивший бизнес, 0/10 баллов)
```

`Task`: название, отрасль, исходный текст, восемь рейтинговых полей, status, score, level, JSON breakdown, timestamps. `Team`: название, JSON-списки interests/skills/tech. `Proposal`: task/team, idea/plan/deadline/link, status, created_at. Уникальная пара task/team защищает от повторной отправки.

Новые `task_verifications` и `proposal_progress` создаются `create_all`; старые столбцы не меняются. Для совместимости старые `confirmed/published` записи без снимка считаются уже подтверждёнными по прежнему ручному процессу; первая правка сохраняет исходный снимок. Каталог вычисляет актуальный балл при чтении, не перезаписывая чужую БД. Для большой базы понадобятся миграции, пагинация и оптимизация сортировки.

`app/main.py` — роутеры, статика, CORS, русские ошибки; `config.py` — настройки; `db.py` — сессии, metadata и включение SQLite FK. Все fetch-вызовы находятся в `static/js/api.js`. Экраны: `constructor.js`, `catalog.js`, `task.js`, `business.js` (свои задачи), `proposals.js` (отклики); `task-actions.js` — подтверждение удаления. Оболочка `app.js`, общие компоненты `helpers.js/ui.js`. Исходный дизайн в `design/` не изменён.

## 8. Технологии

Python 3.11, FastAPI 0.115.12, SQLAlchemy 2.0.40, SQLite, Pydantic 2.11.3, Uvicorn 0.34.2, HTTPX 0.28.1, pytest 8.3.5. Версии закреплены в `requirements.txt`. Фронтенд — статические ES-модули без сборки и фреймворков. Node.js/Docker не нужны.

## 9. Установка и запуск

### Windows — одна команда

Нужен установленный Python 3.11 (доступный через `py -3.11` или `python`). Интернет нужен для первой установки зависимостей. Откройте PowerShell в корне **своей копии** проекта:

```powershell
.\start.bat
```

Можно дважды нажать `start.bat`. Скрипт создаёт `.venv`, восстанавливает pip при необходимости, устанавливает зависимости, создаёт отсутствующий `.env`, загружает seed в пустую БД и запускает один сервер со статикой. При занятом 8000 выбирает 8001–8019 и печатает адрес; чужие процессы не завершает. Существующие `.env` и записи БД не перезаписывает. Остановка своего экземпляра: Ctrl+C в его окне.

Проверенный вариант для независимого запуска рядом с сервером команды:

```powershell
.\start.bat --check
.\start.bat --no-browser --port 18793
```

Эти команды выполняйте в отдельной чистой копии репозитория без `.venv`, `.env` и `.db`, если нужна независимая база. **Один только другой порт не изолирует данные:** в той же папке используется тот же `DATABASE_URL`. Не удаляйте рабочую базу для демонстрации.

### Ручная установка в чистой копии (Windows)

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m app.seed.seed
.\.venv\Scripts\python.exe -m pytest tests -q -p no:cacheprovider
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 18793
```

`Copy-Item` в ручной инструкции предназначен **только для чистой копии без `.env`**. Если Python 3.11 доступен как `python`, замените `py -3.11` на `python`. Активация venv не обязательна. Из активированной venv эквивалентны `pip install -r requirements.txt`, `python -m app.seed.seed`, `uvicorn app.main:app --host 127.0.0.1 --port 18793`.

Сайт: `http://127.0.0.1:18793/`; Swagger: `/docs`; проверка:

```powershell
Invoke-RestMethod http://127.0.0.1:18793/health
Invoke-RestMethod http://127.0.0.1:18793/api/catalog
```

Ожидается `status: ok`, каталог из 5 seed-карточек до собственного демо. Автоматический и ручной запуск проверены на Windows/Python 3.11 в отдельных окружениях. На Linux/macOS предусмотрен `python3.11 start.py`, но отдельной проверки на этих ОС не было. Подробнее: [LOCAL_RUN.md](LOCAL_RUN.md).

## 10. Как проверить — подготовленный пример

Точные синтетические тексты: [docs/DEMO.json](docs/DEMO.json). Ссылки example.com — демонстрационные, не реальный прототип. Используйте свежую seed-базу и локальный режим без ключа.

| Действие в интерфейсе | Ожидаемый результат |
|---|---|
| Бизнес → Алия → создать задачу: название «Демо: обращения клиентов», отрасль «Сервисы», текст «Нужен сервис» | Черновик: **0** |
| Проверить полноту → пока пропустить уточнения → собрать карточку | В контексте только «Нужен сервис»: **0**, прогноз **5** |
| В редакторе проверить и нажать «Подтвердить заполненные поля» | **5**, уровень «Черновик»; ещё не опубликована |
| Вставить восемь значений из `answers` в DEMO.json в соответствующие поля → сохранить | Начислено **0**, прогноз **100**: старый контекст изменён, новый ещё не подтверждён |
| «Подтвердить заполненные поля» | **100**, «Приоритетная», все 7 показателей заполнены |
| Перейти к публикации → обе галочки → опубликовать | **100**, первое место в свежем каталоге при равенстве с более старой seed-задачей |
| Команда Data Sparks → открыть свою демо-задачу → вставить `proposal` → отправить | `pending`, бизнес ещё никого не выбрал |
| Повторить от Civic Code | Два независимых предложения |
| Бизнес → Алия → Предложения → выбрать демо-задачу, принять Data Sparks, отклонить Civic Code | `accepted` / `rejected`, без автоматического решения остальных |
| Команда Data Sparks → Мои отклики → отправить `progress` | Результат ожидает проверки, баллы команды **0** |
| Бизнес → подтвердить результат | Команде **10**, рейтинг задачи остаётся **100** |
| Команда → обновить статусы/страницу | **10** сохранены, повторное начисление недоступно |

Вводить подробности можно на этапе вопросов либо в редакторе; для показа слабой карточки в этом примере вопросы сначала пропускаются. Для выступления до 5 минут заранее откройте DEMO.json для копирования. Автоматический браузерный прогон проверяет все переходы, но не измеряет длительность живого рассказа человека.

Дополнительные проверки: каталог №8 имеет 37,5 балла и доступен для отклика; фильтр `draft` его не скрывает. При PATCH полного подтверждённого поля `data` на другой текст рейтинг 100→80; повторное подтверждение 80→100. Чужой бизнес не может принять/отклонить отклик (403), публикация черновика запрещена (409), неизвестные поля ответа возвращают русскую 422, а не 500.

## 11. Тестовые данные

```powershell
.\.venv\Scripts\python.exe -m app.seed.seed
```

`app/seed/data/`: 5 черновиков с 0/2/4/6/8 заполненными рейтинговыми полями (потенциал 0/20/50/75/100, начислено 0); 5 опубликованных подтверждённых карточек (100/95/37,5/85/60), 5 профилей команд, 5 откликов. Есть все четыре уровня. Пользователи: 1 — Алия, 2 — Тимур; 3–7 — команды.

Seed создаёт таблицы и загружает данные, только если пользователей ещё нет. Повтор не удаляет и не заменяет записи; частично заполненную базу автоматически не дополняет. Для нового демо используйте отдельную копию/отдельный `DATABASE_URL`, не очищайте базу коллег.

## 13. Ограничения

- Вход без пароля, `X-User-Id` можно подменить: только локальная демонстрация, не публичный production.
- Рейтинг проверяет длину и подтверждение, но не истинность и не смысловую полезность. Шаблонная заглушка не равна полноценной языковой модели.
- Внешний AI-провайдер проверен только подменёнными ответами; работоспособность конкретного ключа, модели и тарифа вживую не проверялась.
- Нет регистрации, чата, уведомлений, загрузки файлов, календаря, полного трекера и редактирования профилей команд. Один этап результата, 10 баллов однократно.
- Одна команда может отправить только один отклик на задачу; общего лимита разных команд нет. Если требовать несколько альтернатив от одной команды, эта часть не реализована.
- Прежние подтверждённые записи без снимков принимаются как ранее подтверждённые; ретроспективно доказать подтверждение каждого старого значения нельзя.
- Нет realtime: обновите статусы или страницу. Редактор не является совместным документом с объединением одновременного ввода двух браузеров.
- SQLite и сортировка каталога в памяти предназначены для небольшого MVP. Нет нагрузочного тестирования, промышленной авторизации и системы миграций.
- Проверка секретов по сигнатурам в доступной Git-истории совпадений не нашла, но это не абсолютная гарантия. `.env`, базы и окружения исключены из Git.
- Linux/macOS и реальный публичный хостинг не проверялись; шрифты из Google Fonts при отсутствии сети заменяются системными.

## 14. Развёрнутая версия

Публичной развёрнутой версии нет. Локальная проверка — `http://127.0.0.1:18793/` пока запущен ваш проверочный сервер; обычный `start.bat` печатает выбранный адрес. Сервер команды и его рабочая база во время аудита не останавливались и не перезаписывались.
