# Локальный запуск AI Sana

## Самый простой способ — Windows

1. Откройте папку проекта в Проводнике.
2. Дважды нажмите **`start.bat`**.
3. Дождитесь сообщения «Готово!» — сайт откроется в браузере автоматически.

**Окно запуска оставляйте открытым**, пока пользуетесь сайтом. Остановка — `Ctrl+C` в этом окне. Если Windows спросит о завершении командного файла, подтвердите. Для следующего запуска снова откройте `start.bat`.

Альтернатива из терминала PowerShell в папке проекта:

```powershell
.\start.bat
```

### Что нужно на новом компьютере

Нужен **Python 3.11**. Если рабочая `.venv` уже есть, используется она. Иначе `start.bat` ищет Python 3.11 через `py`, затем `python`.

Если выводится `Python 3.11 is required`, установите Python 3.11 с официального сайта Python, включив Python Launcher и «Add python.exe to PATH», затем снова откройте `start.bat`. Установщик Python скрипт сам не скачивает и не запускает.

## Подключение OpenAI

В корневом `.env` задайте параметры (настоящий ключ храните только в этом локальном файле):

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-4.1-mini
AI_PROVIDER=auto
OPENAI_TIMEOUT_SECONDS=30
OPENAI_MAX_OUTPUT_TOKENS=4000
```

Перезапустите сервер и обновите страницу через `Ctrl+F5`. В конструкторе будет указан режим OpenAI. Описание, сохранённые поля и ответы отправляются OpenAI для уточняющих вопросов и сборки карточки. Ключ во фронтенд не передаётся; `.env` исключён из Git. Рейтинг и выбор команд остаются обычной серверной логикой.

`AI_PROVIDER=auto` включает OpenAI при наличии ключа, иначе использует локальные шаблоны. `openai` требует ключ, `stub` явно включает работу без внешних запросов. При ошибке OpenAI приложение сохраняет введённые данные и предлагает повторить действие либо заполнить карточку вручную.

Проверка подключения на вымышленной задаче, без изменения базы:

```powershell
.\.venv\Scripts\python.exe -m app.check_ai
```

Это два реальных запроса с расходом API-квоты. `GET /api/ai/status` показывает только настройки режима, без платного запроса и без проверки действительности ключа. Для тестов `pytest` настоящий ключ не используется. Дополнительные библиотеки для интеграции не нужны: применяется уже установленный `httpx`.

## Подключение AI: LM Studio или публичный llmster

1. В LM Studio добавьте текстовую instruct/chat-модель и включите сервер на вкладке Developer. Через CLI: `lms server start --port 1234 --bind 127.0.0.1`. Приложение не загружает модели из интернета автоматически.
2. В AI Sana выберите «Бизнес» → **«Настройки AI»**. Адрес по умолчанию: `http://127.0.0.1:1234/v1`.
3. Нажмите **«Обновить список моделей»**, выберите модель и **«Сохранить настройки»**. Для демонстрации на этом компьютере проверена `google/gemma-4-e4b`; список берётся с сервера и может отличаться. Embedding-модель не подходит для диалога.
4. Для публичного llmster укажите его базовый адрес, например `https://ваш-сервер/v1`, либо адрес с префиксом reverse proxy (`https://ваш-сервер/llm/v1`). Если сервер требует авторизацию, введите его API-ключ. При смене адреса сохранённый ключ не отправляется новому серверу.

Настройки привязаны к бизнес-пользователю и сохраняются в SQLite. Ключ не возвращается в API и не сохраняется в браузере. Существующий ключ можно оставить или явно удалить. Исходный текст задачи отправляется только выбранному провайдеру при запуске анализа/сборки; каталог при открытии AI не вызывает. CORS в LM Studio для этого подключения не нужен: к модели обращается Python-бэкенд.

Серверные значения по умолчанию можно задать в `.env`:

```dotenv
AI_BASE_URL=http://127.0.0.1:1234/v1
AI_MODEL=
AI_API_KEY=
AI_TIMEOUT=180
AI_MAX_TOKENS=4096
AI_RESPONSE_FORMAT=auto
```

Пустой `AI_MODEL` — первая доступная текстовая модель. Настройки из интерфейса имеют приоритет над `.env`. После изменения `.env` перезапустите сайт. Старое значение `OPENAI_MODEL` из прежнего шаблона не используется. `OPENAI_BASE_URL` и `OPENAI_API_KEY` поддерживаются как запасные имена.

Первый запрос может занять больше времени на загрузку модели; для местной `google/gemma-4-e4b` при проверке анализ занимал около 74 секунд. При ошибке данные формы остаются, можно повторить запрос или заполнить карточку вручную. Автоматической замены AI на заглушку нет. В расширенных настройках есть режимы JSON Schema / JSON Object / JSON в тексте; по умолчанию совместимость определяется автоматически.

| Ошибка AI | Действие |
|---|---|
| Нет связи (`503`) | Включить сервер и проверить адрес/порт |
| Нет моделей | Добавить текстовую модель на AI-сервер |
| Модель недоступна (`409`) | Обновить список и выбрать доступную модель |
| Доступ отклонён (`502`) | Проверить ключ API выбранного сервера |
| Некорректный ответ (`502`) | Повторить запрос или выбрать другую модель; карточка не изменена |
| Тайм-аут (`504`) | Проверить ресурсы сервера; при необходимости увеличить `AI_TIMEOUT` до 600 секунд |

Контракт подключения: [LM Studio OpenAI compatibility](https://lmstudio.ai/docs/developer/openai-compat), [JSON Schema](https://lmstudio.ai/docs/developer/openai-compat/structured-output).

## Где открывать

Обычно адрес сайта — **http://127.0.0.1:8000/**. Если порт занят, скрипт выбирает свободный из `8000–8019`, печатает точную ссылку и открывает её. Он не останавливает чужие процессы. Повторный запуск при работающем экземпляре может открыть ещё один сервер на следующем порту — сначала остановите прежний через `Ctrl+C`, если второй не нужен.

- Сайт: `http://127.0.0.1:ПОРТ/`
- Документация API: `http://127.0.0.1:ПОРТ/docs`
- Проверка сервера: `http://127.0.0.1:ПОРТ/health` → `{"status":"ok"}`

Это доступ **только с вашего компьютера**, не публикация в интернете. Не открывайте этот MVP наружу без настоящей авторизации: роль и пользователь выбираются без паролей.

## Как проверить все основные функции

1. Выберите **«Бизнес»**, пользователя **«Алия, бизнес-заказчик»**.
2. **«Создать задачу»** → введите описание, название и отрасль → **«Проверить полноту»**.
3. Ответьте на вопросы → **«Собрать карточку»**. Сохранённые, но неподтверждённые поля показывают только прогноз. Проверьте текст и нажмите **«Подтвердить заполненные поля»**, чтобы получить баллы. Правка поля снимает его баллы в редакторе до повторного подтверждения. Для опубликованной задачи каталог сохраняет прежнюю подтверждённую версию, пока владелец не подтвердит дополнения.
4. **«Перейти к публикации»** → проверьте данные → поставьте обе галочки → **«Опубликовать в каталоге»**. Низкий рейтинг не мешает публикации.
5. Переключитесь на **«Команда»**. В каталоге найдите задачу, откройте её, заполните идею, план и срок → отправьте отклик. Ссылка на прототип необязательна; если указываете её, используйте `http://` или `https://`.
6. Для сравнения двух предложений выберите другую команду в выпадающем списке и тоже откликнитесь. Одна команда отправляет один отклик на задачу.
7. Вернитесь к **тому же бизнес-пользователю** → **«Предложения»** → выберите задачу → примите или отклоните отклик. Решение можно отменить и вернуть предложение на рассмотрение. Другие отклики не меняются автоматически. Вкладка **«Мои задачи»** управляет карточками; ссылка **«Предложения»** у карточки открывает отклики именно этой задачи.
8. У выбранной команды откройте **«Мои отклики»** → **«Передать результат этапа»**. Укажите фактически выполненную работу и отправьте на проверку. Бизнес вручную нажимает **«Подтвердить результат · +10»**. Команда получает 10 баллов один раз; обновление страницы сохраняет результат. Баллы команды не меняют рейтинг задачи.
9. Чтобы удалить задачу, выберите её владельца в роли **«Бизнес»**, откройте **«Мои задачи»** или саму карточку → **«Удалить задачу»**. Проверьте название в окне подтверждения. **«Удалить задачу и отклики»** безвозвратно удаляет карточку, её отклики и результаты этапов, включая начисленные за них баллы. **«Отмена»** сохраняет данные. После обновления списка у команд эти отклики исчезнут; остальные задачи и команды останутся.

Также работают поиск, сортировка, фильтры по отрасли и готовности, рекомендации по интересам команды. На телефоне фильтры каталога и список задач в разделе «Предложения» раскрываются кнопкой, сравнение команд прокручивается по горизонтали. В «Моих задачах» карточки отображаются отдельным списком.

## Дополнительные команды

```powershell
# Не открывать браузер, ссылку скопировать самостоятельно:
.\start.bat --no-browser

# Запустить строго на выбранном порту (если занят — понятная ошибка):
.\start.bat --port 8080

# Подготовить проект, запустить автотесты и выйти без сервера:
.\start.bat --check
```

Команды можно запускать из любой папки, указав полный путь к `start.bat`. Сам скрипт переходит в корень проекта, поэтому не создаёт случайные базы в других каталогах.

### Linux / macOS

При установленном Python 3.11 из папки проекта:

```bash
python3.11 start.py
```

Опции те же: `--no-browser`, `--port 8080`, `--check`. Подготовка окружения, зависимостей и БД автоматическая. Автоматизированный запуск проверен на Windows; отдельной проверки Linux/macOS не проводилось.

## Где данные и настройки

- По умолчанию задачи и отклики хранятся в `ai_sana.db` в корне проекта. Для резервной копии остановите сервер и скопируйте этот файл.
- `.env` содержит `DATABASE_URL`. Существующий `.env` никогда не перезаписывается. Если меняете путь к БД, резервируйте соответствующий файл.
- Seed не очищает БД и не создаёт дубликаты при повторном запуске. Тесты используют отдельную тестовую БД.
- Выбор пользователя, фильтры и резервные копии незавершённых форм хранятся в браузере. Завершённые сохранения — на сервере в SQLite.
- `.venv` хранит окружение и отметку об установленных зависимостях; её не нужно добавлять в Git. Автозапуск после перезагрузки компьютера не настраивается.

## Если не запускается

| Сообщение / проблема | Что сделать |
|---|---|
| Python 3.11 не найден | Установите Python 3.11 с Launcher; повторите запуск |
| Не удалось установить зависимости | Проверьте интернет и текст ошибки; снова запустите `start.bat` |
| Нерабочее окружение / неверная версия Python | Закройте сервер, переименуйте только `.venv` в `.venv.backup`, установите Python 3.11 и повторите запуск; `.env` и `.db` не трогайте |
| Не удалось восстановить pip | Скрипт делает это автоматически через `ensurepip`; если восстановление не удалось, создайте окружение заново по строке выше |
| Браузер не открылся | Откройте ссылку, напечатанную после «Готово!», вручную |
| Страница недоступна | Убедитесь, что окно сервера открыто; используйте фактический порт из этого окна |
| Порт недоступен | Попробуйте `.\start.bat --port 8080`; не завершайте незнакомые процессы |
| Не удалось подготовить БД | Проверьте `DATABASE_URL` и права на папку БД; существующую базу не удаляйте |
| Нет кнопки создания задачи | Переключитесь на роль «Бизнес»; на телефоне она есть в «Мои задачи» |
| OpenAI не принимает ключ | Проверьте `OPENAI_API_KEY` в `.env` и перезапустите сервер |
| Исчерпана квота OpenAI | Проверьте квоту и оплату проекта OpenAI; можно продолжить заполнение вручную |
| OpenAI не отвечает / тайм-аут | Повторите запрос позже, проверьте сеть или временно задайте `AI_PROVIDER=stub` и перезапустите сервер |
| Модель недоступна | Проверьте `OPENAI_MODEL` и доступ проекта к выбранной модели |

Архитектура и проверяемый сценарий с точными баллами — [README.md](README.md); правила совместной работы — [AGENTS.md](AGENTS.md). Для проверки рядом с работающей командой используйте отдельную копию и отдельную БД. Другой порт в той же папке сам по себе не изолирует данные.
